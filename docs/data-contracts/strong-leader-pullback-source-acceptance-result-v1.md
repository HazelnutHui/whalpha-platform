# Strong-Leader Pullback Source Acceptance Result V1

## Purpose

`strong-leader-pullback-source-acceptance-result/1.0` evaluates one real or
fixture provider sample against the immutable 20-action / 64-lifecycle
population. It is a provider-selection artifact, not a canonical data family,
Historical Coverage decision, research admission, or strategy result.

The evaluator is pure. It performs no provider request, credential read,
canonical write, outcome calculation, publication, deployment, or scheduler
change.

## Inputs

The result binds:

- the exact Source Acceptance Sample V1 file SHA-256 and logical fingerprint;
- one self-fingerprinted provider/product/sample assessment;
- source schema and non-secret sample fingerprints;
- a reviewed permission fingerprint; and
- the evaluator implementation revision and UTC evaluation time.

The assessment must preserve all cases in the same deterministic order.
Missing, duplicated, substituted, or reordered cases reject evaluation.

## Case and field states

Each case is explicitly `matched`, `absent`, `unsupported`, or `conflicting`
and binds a non-secret result-evidence fingerprint. Each required field is
separately `provided`, `explicit_not_applicable`, `missing`, `unsupported`, or
`conflicting`.

`explicit_not_applicable` requires positive retained evidence. It cannot
replace stable identity, source availability/revision semantics, lifecycle
status dates, first/last tradability, termination reason, or the exact action
ratio/consideration required by the frozen action sample.

## Permission gate

The assessment records, without credentials or provider payload bodies,
whether the reviewed terms permit:

- a production-representative sample;
- private research on Dell;
- local evidence retention;
- stable-identifier use;
- public display of derived metrics; and
- documented termination obligations.

Unknown permission is false. A technical match cannot override permission.

## Qualifications

- `sole_primary_candidate`: every case and required semantic is complete,
  stable identity is verified for all 84 cases, no conflict exists, and all
  permission gates pass.
- `corroborator_only`: at least one matched case supplies at least one required
  field, the sample and private Dell use/retention/identifier permissions pass,
  and only complete semantics or public-derived-display permission prevents
  primary qualification.
- `rejected`: no matched case supplies a required field.

A source is also `rejected` when private research, local retention, stable-ID
use, production-sample representativeness, or termination obligations are not
cleared, even if its payload is technically complete.

Even `sole_primary_candidate` selects no source and authorizes no promotion.
A separate mapping review, source-resolution policy, canonical publication,
and full performance-admission replay remain mandatory.

## Fixed non-authority

Sole-primary selection, canonical promotion, Historical Coverage, performance
admission, true labels, parameter selection, Candidate activation, network
requests, canonical writes, and Production writes remain false or zero in
every result.
