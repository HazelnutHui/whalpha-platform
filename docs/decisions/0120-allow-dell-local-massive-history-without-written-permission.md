# ADR 0120: Allow Dell-Local Massive History Without Written Permission

## Status

Accepted by explicit user direction

## Date

2026-09-01

## Context

The 2026-08-28 engineering review did not establish written Massive permission
for retained derived research or equal-capability guest display. That finding
previously blocked the Historical Pilot alongside incomplete lifecycle and
terminal-outcome evidence.

On 2026-09-01 the user explicitly directed the project to continue historical
acquisition without obtaining separate Massive written permission and to
download automatically after technical gates pass. The user is not asking the
project to represent that permission exists.

## Decision

For Dell-local acquisition, normalization, storage, and private research only,
remove written Massive permission as an execution blocker. Preserve the dated
source-policy finding as an explicit limitation rather than rewriting it as a
cleared permission conclusion.

This decision does not change these gates:

- exact account endpoint access and rate limits;
- immutable source custody before mapping;
- complete same-session Identity and unadjusted EOD validation;
- lifecycle, delisting, merger/successor, and terminal-outcome completeness;
- daily point-in-time Universe Membership;
- canonical corporate actions and reconciled adjustment ledgers;
- transitive Historical Coverage before real strategy evaluation; and
- quarantine of ambiguous or incomplete evidence.

Historical acquisition remains Dell-only. It does not automatically authorize
raw or derived historical publication, OCI transfer, guest display, Snapshot
generation, model activation, performance claims, or option-return claims.
Those remain separate transitions. Existing equal guest/credential product
capability is unchanged; no owner-only web product tier is created.

The first live operation remains the exact three-session 2026-07-14 through
2026-07-16 Pilot. After its acquisition and canonical quality gates pass, the
300-session plan may continue serially with durable batch custody and fail-stop
recovery, without asking for a new chat confirmation for every batch.

## Consequences

- Absence of written Massive permission no longer blocks Dell-local historical
  acquisition.
- The project still states accurately that written permission was not
  established.
- No public-serving right is inferred from this user risk decision.
- Technical and data-quality gates remain fail-closed and cannot be waived by
  the same instruction.
- A later compatible provider can add or supersede source observations without
  rewriting canonical stable identities or deleting prior revisions.

## Alternatives Considered

### Continue blocking all acquisition

Rejected by the user's explicit direction.

### Treat the direction as proof of provider permission

Rejected because the user can direct project behavior but cannot turn an
unverified third-party permission into verified evidence.

### Publish the resulting research automatically

Rejected because acquisition, canonical Apply, research readiness, and public
serving are separate authorities and evidence states.
