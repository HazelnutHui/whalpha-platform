# ADR 0266: Separate Outcome-Blind Method Engineering from Performance Admission

- Status: Accepted
- Date: 2026-09-14

## Context

The first Strong-Leader Pullback experiment, formula, parameter budget, and
synthetic mechanics are preregistered. Dell also has a complete fixed price,
stable-identity, and reconstructed Membership input interval. The final
transitive review nevertheless rejects performance admission because complete
corporate-action neutrality, adjustment coverage, lifecycle outcomes, and
Historical Coverage are absent.

ADR 0195 deliberately rejects choosing a better-covered security subset or a
lower session-completeness threshold. ADR 0265 therefore stopped before real
triggers and outcomes. That strict decision remains correct for parameter
selection, validation, holdout use, performance reporting, Candidate
activation, and any claim that the model works.

Making one commercial source response a prerequisite for all further
engineering would conflate two different questions: whether the method can be
implemented transparently, and whether the available data can support a real
performance conclusion. The owner chose to continue the former without making
LSEG or another named vendor a near-term dependency.

## Decision

Create one immutable method-engineering launch review bound to the final
pre-research rejection and the unchanged V1 experiment.

The launch review may authorize only:

- implementation and testing of the already registered feature and signal
  method;
- synthetic, adversarial, and property tests;
- private outcome-blind feature-quality and coverage diagnostics whose input
  tier remains `reconstructed_latest_vintage_method_engineering_only`;
- provider-neutral label and sensitivity interfaces with no real label
  population; and
- Quant Research Lab method, data-readiness, and limitation views with no
  performance result.

It does not move the experiment from `preregistered_data_blocked` to
`development`. It does not authorize real forward outcomes, parameter
selection, formal validation, holdout access, performance claims, Candidate
activation, canonical data writes, publication, deployment, or an external
request.

The report must bind the exact pre-research review SHA-256 and logical
fingerprint, experiment and evaluation-policy fingerprints, implementation
revision, fixed interval, input-family fingerprints, unresolved formal
blockers, allowed actions, and prohibited actions. It is written only to a new
owner-only state directory outside `/data` and formally reread.

Any feature distribution or diagnostic observed in this engineering lane is
not independent performance evidence and cannot be reused as validation or
holdout evidence. If it motivates a formula or parameter-grid change, that
change requires a new preregistered experiment version before outcomes are
opened.

## Consequences

- Strong-Leader Pullback and the Lab method surface can begin without waiting
  for LSEG, ICE, S&P, or another provider.
- The project gains no provisional Sharpe ratio, return, win rate, Alpha,
  parameter winner, or model ranking.
- Missing corporate-action and terminal evidence remains visible and cannot
  be converted into a neutral row, a dropped survivor, or an inferred zero.
- The existing strict performance gate and complete-session rule are not
  weakened or superseded.
- A future source can still expand the same provider-neutral evidence families
  and trigger a versioned performance-admission review.

## Rejected alternatives

### Lower the complete-session threshold

Rejected because a post-gap percentage would allow corporate-event
missingness to select the research population.

### Drop unresolved instruments or sessions

Rejected because lifecycle and terminal gaps are not random and could create
survivorship bias.

### Treat method engineering as formal development

Rejected because the current data gate is explicitly failed. Engineering
readiness is not evidence sufficiency.

### Wait for one named vendor before writing any strategy or Lab code

Rejected because vendor choice is independent of transparent, outcome-blind
method implementation.
